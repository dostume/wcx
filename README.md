# WCX (WeKit) — 微信 Xposed 功能增强模块

**仓库主页：https://github.com/dostume/wcx** · 下载：[Releases](https://github.com/dostume/wcx/releases)

> 基于上游 WeKit 的增强分支，保留上游全部 270+ 功能，另新增**消息定时发送**、**自定义通知铃声**、**一键关闭所有日志**、**联系人选择全屏化**等能力。本仓库通过 GitHub Actions 自动同步上游更新并云端构建正式签名 APK（详见下方[自动化构建](#-本仓库自动化构建无需本地环境)）。

## 📥 下载与安装

1. 到 [**Releases**](https://github.com/dostume/wcx/releases) 页面下载 APK（推荐 `app-standard-arm64-v8a-release.apk`）
2. 安装后在 **LSPosed**（或其他 Xposed 管理器）中启用本模块，作用域勾选 **微信**
3. 强制停止微信并重新打开，模块生效

> 所有 Release 均使用同一正式签名（证书 SHA-256 `0c6b74af…`），可互相直接覆盖安装，无需卸载重装。

## 🆕 本仓库相比上游新增的功能

以下功能为本仓库独有，上游 [Johnny520/wcx](https://github.com/Johnny520/wcx) 暂未包含：

> **一句话总结**：在上游基础上新增定时发送消息、自定义通知铃声、一键关闭所有日志、联系人选择全屏化，并维护每日自动同步上游的云端构建。

### 新功能

- **定时发送消息（消息长按菜单）**：长按任意消息 → 「定时发送」，支持
  - 指定时间发送，可选每天重复或仅一次
  - 文本 / 图片 / 视频 / 语音 / 文件等多种消息类型
  - **多选消息**打包为一条定时任务（自动从数据库重建完整消息对象）
  - 创建任务零下载零等待（复读式设计：本地已有文件直接复用，未落地文件发送时现场解析）
  - 「取消定时发送」按主题列出并批量删除任务
- **单条消息定时发送（输入栏）**：在指定时间发送消息到群聊或私聊
- **自定义通知铃声**：为任意联系人 / 群聊单独设置通知铃声，按会话覆盖微信默认提示音
- **关闭所有日志**：设置页一键开关，开启后不输出、不记录任何模块日志（logcat 与日志文件，含崩溃日志），降低性能开销、避免隐私暴露
- **长昵称双行显示**：聊天页群成员昵称与会话列表标题过长时折为两行完整显示，不再单行截断，同时解除群昵称 240dp 宽度限制
- **联系人选择窗口全屏化**：批量标为已读、群发消息等所有需要挑选联系人的功能，选择窗口铺满全屏，长列表更好找

### 维护与优化

- 程序内链接与更新源全部指向本仓库，GitHub Actions 云端自动构建，每日自动同步上游并发布新版
- ProGuard 深度瘦身，安装包体积明显缩小
- 定时发送多选/媒体链路、DEX 缓存、root 检测等多项稳定性加固

## 🤖 本仓库自动化构建（无需本地环境）

本仓库配置了全自动流水线 `Sync Upstream & Build APK`：

| 机制 | 说明 |
|---|---|
| **每日自动检查** | 每天北京时间 09:00 检查上游 [Johnny520/wcx](https://github.com/Johnny520/wcx) 是否更新 |
| **自动同步出包** | 上游有更新 → 自动合并本仓库改动 → 云端构建 4 个 APK → 自动发布到 Releases（标签 `auto-<上游提交号>`） |
| **无更新省配额** | 上游无更新时跳过构建，不消耗 Actions 时长 |
| **手动出包** | Actions 页 → 选工作流 → Run workflow；勾选 `force_release` 可强制发布 Release |

**日常使用只需记住**：有新版本时到 [Releases](https://github.com/dostume/wcx/releases) 下载最新的版本即可，全程零操作。

## ❓ 帮助 / 常见问题

<details>
<summary><b>启用模块后微信没有变化？</b></summary>

确认 LSPosed 作用域已勾选微信 → 强制停止微信 → 重新打开。首次启动可能弹「DEX 缓存更新」，点开始适配即可（适配完成后不再弹出）。
</details>

<details>
<summary><b>每次启动都弹「N 个功能需要更新 DEX 缓存」且关不掉？</b></summary>

点「开始适配」让它完成；若适配后重启仍弹，使用「调试 → 重置适配信息」后重启两次微信。
</details>

<details>
<summary><b>主界面「打开微信」等按钮提示无法执行 su？</b></summary>

应用会依次尝试 9 个 su 路径并回退自动探测。若仍失败，检查 root 管理器（Magisk/KernelSU/APatch）的**排除名单（DenyList）/隐藏应用**里是否包含本模块应用本体——被排除的应用拿不到 su，需在管理器中移出名单。
</details>

<details>
<summary><b>定时发送的图片/语音/视频创建任务会卡住或失败吗？</b></summary>

不会。创建任务只做瞬时本地检查（零下载零等待）。已播放过的语音、已看过的视频会直接复用本地文件；未播放过的媒体在发送时刻现场解析，本地无文件时会从聊天记录数据库重建。唯一边界：从未加载过的媒体在发送时刻可能因微信无对应通道而失败，图片有 CDN 兜底。
</details>

<details>
<summary><b>定时消息重复发送？</b></summary>

本仓库已修复双通道（进程内定时器 + 系统闹钟）竞态问题并加入在途互斥。若仍遇到，请到「调试 → 复制调试信息」导出日志反馈。
</details>

<details>
<summary><b>如何反馈问题？</b></summary>

开启「调试 → 崩溃拦截」与「调试 → 复制调试信息」，附上导出的日志提交 Issue。
</details>
